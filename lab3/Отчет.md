### Текст задачи
Перезарядка Пистолета. Измените сущность Пистолет из задачи 1.5.1. Модификация предполагает внесение следующих дополнительных требований: имеет максимальное количество патронов. Максимальное количество устанавливается во время создания пистолета и не может быть изменено позднее. У пистолета можно узнать, какое максимальное количество он вмещает. Может быть перезаряжен. Для перезарядки необходимо передать пистолету число, которое будет означать количество заряжаемых патронов. Если передано отрицательное число, необходимо выбросить ошибку, объясняющую, что отрицательного числа патронов быть не может. Если передано слишком большое число патронов — необходимо лишние вернуть. ### Алгоритм решения
Класс Pistol (пакет ru.vozhakov.weapons) хранит максимальную вместимость в поле с модификаторами private и final. Значение задаётся один раз в конструкторе и больше не меняется, а узнать его можно через геттер getMaxAmmo. Конструктор проверяет вместимость: если она не больше нуля, выбрасывается IllegalArgumentException, так что пистолет с нулевой или отрицательной обоймой создать нельзя. Метод reload сначала отбрасывает отрицательное число патронов, выбрасывая ошибку с поясняющим текстом. Затем он прибавляет новые патроны к уже заряженным. Если сумма превышает вместимость, в пистолете остаётся ровно максимум, а разница возвращается как лишние патроны; если не превышает, возвращается 0. Метод discharge запоминает текущее число патронов, обнуляет его и возвращает запомненное значение. Текущее количество показывает метод ammo, а isLoaded возвращает true, если патронов больше нуля. Выстрел работает как раньше: при наличии патронов печатается «Бах!» и один патрон списывается, иначе печатается «Клац!». В main вместимость, число заряжаемых патронов и число выстрелов вводятся с клавиатуры. Ошибочный ввод (не число, отрицательное значение) перехватывается, выводится сообщение, и значение запрашивается снова. При вводе из условия (7, 3, 5 выстрелов, 8, 2 выстрела) вторая перезарядка заполняет пистолет до 7 и возвращает 1 лишний патрон, поэтому вывод совпадает с ожидаемым.

## Задача 3
### Текст задачи
Жёлтые страницы. Необходимо разработать сущность ТелефонныйСправочник, который будет использоваться для создания справочника со списком телефонов и имён, с целью поиска телефона по имени. Будем считать достаточным хранение пар телефон-строка, например "89003337788 - Вася". Состояние сущности описывается набором пар "телефон – имя", причём и телефон, и имя являются строками. В целях упрощения задачи будем считать, что одному имени всегда соответствует один телефон, и один телефон соответствует одному имени. Инициализация сущности выполняется без аргументов. Поведение сущности описывают следующие действия: добавление новой пары "телефон – имя" (как два отдельных аргумента), конкретное местоположение добавленной пары не важно; если добавляемое имя уже есть в списке, то имеющийся телефон заменяется на новый, и затем старый телефон возвращается из метода. Удаление значения: для удаления необходимо указать имя удаляемого контакта, после чего удаляется вся пара. Получение значений: для получения необходимо указать имя контакта, тогда возвращается его телефон. Может быть приведён к строке, строка должна представлять собой полный перечень всех хранимых пар. Можно проверить, есть ли конкретный телефон или конкретное имя в списке. Можно узнать текущее количество контактов. Можно запросить в виде массива все пары, все телефоны, все имена. Можно получить массив всех имён, указав часть названия (начиная с первого символа). Продемонстрируйте работоспособность решения на примерах.

### Алгоритм решения
Класс PhoneBook (пакет ru.vozhakov.phonebook) хранит два параллельных массива строк: телефоны и имена. Элементы с одинаковым индексом образуют одну пару. Конструктор без аргументов создаёт оба массива пустыми. Размер массива в Java фиксирован, поэтому для добавления и удаления написан вспомогательный метод resize: он создаёт массив нужной длины и копирует в него старые значения. Поиск позиции значения выполняет метод indexOf, который возвращает индекс или -1, если значения нет. Метод add сначала отклоняет пустой телефон или имя. Затем он проверяет, что телефон не записан на другое имя, иначе нарушилось бы условие «один телефон — одно имя». Если имя уже есть, телефон заменяется и метод возвращает старый номер; если имени нет, оба массива увеличиваются на один элемент, пара записывается в конец, и метод возвращает null. Метод remove находит имя, сдвигает все следующие пары на одну позицию влево и укорачивает массивы; он возвращает удалённый телефон или null, если имени не было. Метод getPhone возвращает телефон по имени. Методы containsName и containsPhone проверяют наличие значения через indexOf, size возвращает длину массива имён. Метод getPairs собирает массив строк вида «телефон - имя», а getPhones и getNames возвращают копии массивов, чтобы снаружи нельзя было испортить данные справочника. Метод findNamesByPrefix проходит по именам дважды: сначала считает подходящие (метод startsWith), чтобы создать массив нужного размера, затем заполняет его. Метод toString склеивает все пары через запятую. В main справочник управляется через текстовое меню: пользователь выбирает действие номером и вводит данные, а ошибки добавления выводятся на экран и не прерывают программу.

## Задача 4
### Текст задачи
Автомат. Создайте такой подвид сущности Пистолет из задачи 2.1.5, который будет совпадать с ней во всех отношениях, кроме следующего: имеет скорострельность (целое число, неизменяемое), которая обозначает количество выстрелов в секунду, поддерживаемое данным автоматом. Скорострельность всегда положительное число. При вызове Стрелять количество выстрелов соответствует скорострельности (например, при скорострельности 3 выводится три строки с текстом выстрела). Умеет Стрелять N секунд, что приводит к количеству выстрелов, равному N, умноженному на скорострельность. Инициализация может быть выполнена следующими способами: без параметров — скорострельность 30, вместимость 30; с указанием максимального числа патронов — скорострельность будет равна половине обоймы; с указанием максимального количества патронов в обойме и скорострельности.

### Алгоритм решения
Класс AutomaticRifle наследуется от Pistol через extends, поэтому перезарядка, разрядка, проверка заряда и максимальная вместимость берутся у пистолета без изменений. Новое поле fireRate объявлено как private final, то есть скорострельность задаётся один раз при создании. Конструкторов три. Конструктор без параметров вызывает `this(30, 30)`. Конструктор с вместимостью вызывает `this(capacity, capacity / 2)`, так что скорострельность равна половине обоймы. Полный конструктор первой строкой вызывает `super(capacity)`: пистолет сам проверяет вместимость. После этого автомат проверяет, что скорострельность положительна, иначе выбрасывает IllegalArgumentException. Метод shoot переопределён: он fireRate раз вызывает `super.shoot()`, то есть одиночный выстрел пистолета. Поэтому на каждый выстрел печатается «Бах!» или «Клац!» и списывается патрон. Перегруженный метод shoot(int seconds) отклоняет отрицательное число секунд и вызывает очередь shoot() нужное количество раз, что даёт N × скорострельность выстрелов. Метод toString переопределён и дополнительно показывает скорострельность. В main показаны все три способа создания: автомат по умолчанию выводится сразу, а для двух других вместимость и скорострельность вводятся с клавиатуры. Затем автомат заряжается, даёт одну очередь, стреляет заданное число секунд и разряжается.

## Задача 2
### Текст задачи
Сравнение точек. Измените сущность Точка из задачи 1.4.1. Переопределите метод сравнения объектов по состоянию таким образом, чтобы две точки считались одинаковыми тогда, когда они расположены в одинаковых координатах.

### Алгоритм решения
Класс Point (пакет ru.vozhakov.geometry) хранит координаты x и y в полях private final и выводится в виде {x;y}. Метод equals, унаследованный от Object, по умолчанию сравнивает ссылки, так же как оператор `==`: две разные точки с одинаковыми координатами считались бы разными. Поэтому equals переопределён. Если передан тот же самый объект, сразу возвращается true. Если передан null или объект другого класса (сравниваются через getClass), возвращается false. Иначе аргумент приводится к Point, и сравниваются обе координаты. Вместе с equals переопределён hashCode через Objects.hash(x, y). По правилам Java одинаковые по equals объекты обязаны иметь одинаковый хеш-код, иначе точки неправильно работали бы в HashSet и HashMap. В main с клавиатуры вводятся две точки. Затем выводится, один ли это объект (`==`), равны ли они по equals, равна ли точка самой себе и равна ли она null. При одинаковых координатах `==` даёт «нет», а equals — «да».

## Задача 3
### Текст задачи
Возведение в степень. Создайте метод, принимающий две строки, в которых будут записаны числа X и Y. Возвращает метод результат возведения X в степень Y. Для преобразования строки в число следует использовать метод Integer.parseInt, а для возведения в степень метод Math.pow. Вызовите разработанный метод, передав туда параметры командной строки, полученные точкой входа в программу. Реализуйте метод так, чтобы для возведения в степень и преобразования строки использовались короткие имена статических методов.

### Алгоритм решения
Метод power находится в классе Power пакета ru.vozhakov.main. Он статический, поэтому вызывается без создания объекта: `Power.power(x, y)`. В начале файла стоят статические импорты `import static java.lang.Integer.parseInt;` и `import static java.lang.Math.pow;`. Благодаря им в коде пишутся короткие имена parseInt и pow вместо Integer.parseInt и Math.pow. Метод превращает обе строки в целые числа через parseInt и возводит первое во второе через pow, результат имеет тип double. В main значения берутся из массива args, то есть из параметров командной строки. Если параметров меньше двух, выводится подсказка, как запустить программу, например `java -cp out ru.vozhakov.main.Main 2 10`. Если параметр не является целым числом, parseInt выбрасывает NumberFormatException, и main перехватывает его и печатает понятное сообщение.

# Задание 8

## Задача 2
### Текст задачи
Патроны наследникам. Измените класс Weapon из задачи 2.4.1 таким образом, чтобы любой класс-наследник мог непосредственно работать с полем, хранящим количество патронов, заряженных в оружии. Обратите внимание, что метод разрядки Пистолета, усложнившийся при решении задачи 2.4.1, снова можно упростить.

### Алгоритм решения
Поле ammo в классе Weapon объявлено с модификатором protected вместо private. Такое поле доступно внутри самого класса, во всех его наследниках и в классах того же пакета, но остаётся закрытым для остального кода, например для Main и Shooter. Поэтому Pistol и AutomaticRifle работают с патронами напрямую, без обходных путей через методы родителя. При private-поле разрядку пришлось бы делать через load(0), который возвращает старое количество, а перезарядку — через ammo() и load. Теперь discharge просто запоминает ammo, присваивает полю 0 и возвращает запомненное значение. Метод reload тоже напрямую складывает ammo с новыми патронами и записывает результат в поле.
